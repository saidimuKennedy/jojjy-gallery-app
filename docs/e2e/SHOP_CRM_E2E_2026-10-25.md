**Scope:** Create a merch product in the CRM with a price and stock, then verify
the public Shop reflects it end to end with Playwright.

**Environment**
- Public app: `http://localhost:3000` (dev)
- CRM: `http://localhost:3001` (dev)
- Shared Postgres: local `jojjy_gallery_crm` on port 5433
- Test product: synthetic `E2E Studio Tee`, one variant `M / Black`

## Issues found

1. **No promo/discount/coupon capability exists.** There is no schema, API, or
   CRM UI for promo codes, sale prices, or discounts in either repo. Only a
   fixed variant price can be authored and verified. If V1 requires promotions,
   this is missing scope, not a bug in the price path.
2. **Price formatting dropped trailing zeros.** The app rendered `$ 42.5` and
   `$ 55` for `42.50` and `55.00`. Fixed by formatting shop prices with two
   decimals (`lib/utils.ts`, covered by `lib/utils.test.ts`).
3. **CRM product list has no price column.** Staff can verify a price only by
   opening the edit dialog. Observation; no data error.
4. **Local cookie collision between ports.** CRM (`:3001`) and public app
   (`:3000`) both use `next-auth.session-token` on `localhost`, so switching
   between them produces `JWEDecryptionFailed` and a stale-looking session.
   Workaround for E2E: clear cookies between apps, use separate browser
   contexts, or use distinct local hostnames. Production uses distinct domains.
5. **Payment completion was later exercised in test mode.** See the
   Paystack section below. Test refunds were accepted by Paystack but remained
   `processing`/`pending`; no live charge or settled refund has been observed.
6. **Small serif UI labels were hard to read.** Shop labels used Cormorant
   Garamond at 12px/400 and body copy used 300 weight. Fixed: Public Sans is
   loaded at 600/700 and used for the body and small labels; display serif is
   reserved for headings. Verified by computed styles and screenshot.

## Reproduce

1. `npx prisma migrate deploy` in the CRM repo against the shared DB.
2. `npm run prisma:seed` in the CRM repo (creates Admin role + seed user from
   `CRM_SEED_EMAIL` / `CRM_SEED_PASSWORD`).
3. Start CRM on `:3001` and the public app on `:3000`.
4. Create a product under CRM → Merch, then inspect `/shop` and
   `/shop/product/<slug>`.
5. Clear cookies when switching between `:3000` and `:3001`.

## Additional fixes from this pass

1. **Checkout no longer leaves orphan PENDING orders.** If Paystack
   initialization fails after the order row is created, the order is marked
   `FAILED`, ticket reservations are released, and the provider message is
   returned (`502`) instead of a generic 500.
2. **Partial refunds use the charge currency.** CRM refunds are stored in order
   currency (USD); Paystack refunds the transaction currency (KES). Partial
   provider amounts are now converted with the order's actual
   `paystackChargeAmount`, so USD $4 becomes KES 520 rather than KES 4.
3. **Refund approve/submit are serialized.** Refund and order rows are locked;
   APPROVED → SUBMITTED is claimed atomically; concurrent approvals cannot
   double-submit.
4. **Refund requests are serialized.** The order row is locked before the
   refundable balance is checked, preventing concurrent over-refunds.
5. **Provider refund amount/currency is validated** against the order's charge
   amount; mismatches become `NEEDS_ATTENTION` instead of being accepted.
6. **Full refunds of unfulfilled merch restock the variant.** Fulfilled orders
   and original artworks remain manual inventory decisions; tickets are
   invalidated and refunded music access is revoked.
7. **Refund request accepts order id or Paystack reference.** The UI already
   claimed both; the server now resolves both to the same order.
8. **App order views show refunded / partially refunded.** The order API exposes
   `paymentStatus`, and the confirmation/account pages no longer call a
   refunded order “Payment pending”.
9. **CRM Overview no longer reserves an empty right column when there is no
   upcoming event.** The grid uses 2 columns (or 3 with an event), and the
   “Continue working” card was moved below the grid at full width.

## Residual decisions / not automated

- Refunded **unchecked tickets** now return capacity automatically; checked-in
  tickets are voided but keep their seat consumed.
- Refunded **original artworks** are not relisted (`AVAILABLE`); this stays a
  manual operator decision.
- **Fulfilled** merch is not restocked automatically; only unfulfilled product
  orders are returned to stock on a processed full refund.
- A refund whose Paystack submission fails before a provider id exists becomes
  `NEEDS_ATTENTION`; the UI has no safe retry path yet. Operators must resolve
  it with Paystack support/manual SQL rather than blindly resubmitting.
- Temporary QA staff/buyer accounts, test product/event, orders, tickets, and
  refunds were removed from the local database after all refunds reached
  `PROCESSED`.
